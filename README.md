# Shalost FOTUR

Локальное приложение для Linux и Windows для работы со своим аккаунтом Pulse РТУ МИРЭА: вход через официальный сайт, поиск QR-кодов, подтверждение присутствия и управление из Telegram.

Форк проекта [Woonze/Shalost_MIREA](https://github.com/Woonze/Shalost_MIREA).

> Проект не связан с РТУ МИРЭА и Pulse. Используйте его только для собственного аккаунта и в соответствии с правилами учебного заведения.

## Чем этот форк отличается от оригинала

- Работает в Linux: сборка, AppImage, снимок экрана через mss, автоклик через XTEST, значок и шрифты из системы.
- Аккаунтов может быть несколько — у каждого свой профиль Chrome и своя сессия.
- Режим лекции: СДО, Pulse и само занятие открываются в одном окне браузера, а QR и кнопка «ПОДТВЕРЖДАЮ» ищутся прямо во вкладках — снимки экрана для онлайн-занятий не нужны.
- Автоматический вход по сохранённому паролю, включая двухшаговый SSO и пропуск необязательных шагов Keycloak.
- Telegram-бот с кнопками: состояние, запуск режимов, аккаунты, ссылка на занятие и код двухфакторной проверки.

## Что делает приложение

- Главный интерфейс запускается сразу и не зависит от загрузки Pulse.
- Вход выполняется в обычном окне Chrome или Chromium, включая 2FA. Сессия остаётся в профиле браузера.
- Сессии всех аккаунтов проверяются при запуске; имя из Pulse видно на главном экране.
- QR-коды Pulse ищутся на всех экранах раз в 2 секунды, а в режиме лекции — прямо во вкладках браузера.
- Окно «Контроль присутствия» в MTS Link распознаётся и подтверждается автоматически.
- Три разных QR подтверждаются подряд, после чего действует пауза, по умолчанию 10 минут. Повтор уже подтверждённого QR не засчитывается, на MTS Link пауза не влияет.
- Найденный QR подтверждается за каждый отмеченный аккаунт.
- Понятный журнал остаётся в окне, полный технический журнал сохраняется в файл.

## Установка в Linux

Нужен x86-64 дистрибутив с glibc 2.35 или новее и установленный Google Chrome либо Chromium: приложение берёт первый найденный браузер из PATH.

1. Скачайте сборку из Releases:
   - `Shalost-FOTUR-x86_64.AppImage` — один файл, `chmod +x` и запуск;
   - `Shalost-FOTUR-linux-x86_64.tar.gz` — portable-вариант. Распакуйте архив и запустите `./Shalost-FOTUR` либо `./install.sh` для ярлыка в меню приложений.
2. Нажмите «Войти в Pulse», войдите обычным способом и завершите 2FA.
3. Нажмите «Начать сканирование» или «Открыть лекцию».

Если AppImage не запускается из-за отсутствия FUSE, используйте `./Shalost-FOTUR-x86_64.AppImage --appimage-extract-and-run`.

## Установка в Windows

Нужен Windows 10/11 и установленный Google Chrome.

1. Скачайте сборку из Releases:
   - `Shalost-FOTUR-Setup-…exe` — установщик с ярлыком;
   - `Shalost-FOTUR-portable.zip` — portable-вариант. Распакуйте архив целиком и запустите `Shalost-FOTUR.exe`.
2. Дальше всё как в Linux: вход в Pulse, затем сканирование или режим лекции.

Cookie вручную копировать не нужно. Если браузер или Pulse вернул ошибку, откройте нижний журнал: статус и причина остаются видны, а поиск QR продолжится.

## Несколько аккаунтов

Один компьютер на двоих — обычное дело, поэтому аккаунтов может быть сколько угодно. Список живёт на странице «Настройки»:

- «Добавить аккаунт» создаёт новый профиль Chrome с собственной сессией;
- точкой отмечается активный аккаунт — с ним работают кнопки «Войти в Pulse» и «Открыть лекцию»;
- отметка QR означает, что аккаунт подтверждает найденный код. Один QR подтверждается за все отмеченные аккаунты по очереди;
- «Пароль» сохраняет логин и пароль для автоматического входа;
- «Выйти» удаляет сессию аккаунта, «Удалить» — сам аккаунт вместе с профилем и паролем.

Профиль прежних версий переносится в папку первого аккаунта при первом запуске.

## Автоматический вход

Если для аккаунта сохранены логин и пароль, приложение само проходит вход в открытом окне Chrome: находит страницу входа, заполняет форму — в том числе когда логин и пароль спрашивают на разных экранах — и пропускает необязательные шаги вроде предложения донастроить аккаунт. Pulse и СДО пользуются одним входом, поэтому в режиме лекции вкладка СДО входит теми же данными.

Когда сайт просит код двухфакторной проверки, появляется окно с запросом кода. Тот же запрос уходит в Telegram, если бот подключён: код можно прислать сообщением, и окно закроется само.

Если сессия потерялась, а пароль сохранён, приложение входит само — без окна браузера, при очередной проверке сессий или по команде `/login`. Вернуть сессию можно, не подходя к компьютеру. Повторная попытка для одного аккаунта делается не чаще раза в десять минут.

Пароль хранится в системном хранилище: Credential Manager в Windows, KWallet или GNOME Keyring в Linux. В файлах приложения пароля нет, в `settings.json` попадает только логин. Если системного хранилища нет, приложение сообщит об этом и предложит входить вручную. Помните, что сохранённый пароль доступен любому, кто работает под вашей учётной записью в системе.

## Режим лекции

Кнопка «Открыть лекцию» открывает окно браузера со вкладками СДО (online-edu.mirea.ru) и Pulse. Ссылка на занятие вводится рядом с кнопкой и открывается третьей вкладкой; она запоминается до следующего раза.

Приложение следит за вкладками: нажимает «ПОДТВЕРЖДАЮ» в MTS Link и распознаёт QR на снимке вкладки. Кнопка нажимается и в неактивной вкладке — Chrome не доставляет туда настоящие события мыши, поэтому используется событие страницы.

Режиму не нужны снимки экрана, поэтому он работает в любом сеансе, включая Wayland.

## Снимки экрана и автоклик

Кнопка «Начать сканирование» ищет QR на всех экранах — это нужно, когда QR приходит мимо управляемого браузера: десктопный клиент MTS Link, другой браузер, чужой скриншот.

Снимок всех экранов делает `ImageGrab` в Windows и `mss` в Linux, автоклик — `mouse_event` в Windows и XTEST в Linux, с запасным вариантом `xdotool`. В сеансе Wayland ни снимок экрана, ни синтетический клик недоступны: X-сервер не отдаёт содержимое окон Wayland. Приложение пишет об этом в журнал; для онлайн-занятий используйте режим лекции.

## Управление из Telegram

Приложение умеет отчитываться о событиях и принимать команды из личного чата с вашим ботом.

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. В настройках нажмите «Подключить бота» и вставьте токен.
3. Приложение покажет код привязки. Отправьте боту `/start <код>` — чат привяжется.

Команда `/menu` открывает экран с кнопками: открыть или закрыть лекцию, запустить или остановить поиск QR, задать ссылку на занятие, перейти к аккаунтам, войти заново и обновить сводку. Подписи кнопок зависят от состояния, а экран обновляется прямо в чате. На экране аккаунтов видно, кто вошёл и кто подтверждает QR; нажатие включает или выключает аккаунт.

Те же действия доступны командами: `/status`, `/login`, `/scan`, `/stop`, `/lecture`, `/lecture <ссылка>`, `/close`. Когда приложение ждёт код двухфакторной проверки, обычное сообщение с кодом уходит в форму входа.

Команды и нажатия принимаются только из привязанного чата. Токен бота хранится в системном хранилище рядом с паролями аккаунтов. Бот управляет приложением на вашем компьютере, поэтому работает, только пока оно запущено.

## Сессия и приватность

Сессия хранится только в профиле Chrome:

    %LOCALAPPDATA%\Shalost\accounts\<аккаунт>\pulse-chrome-profile      (Windows)
    ~/.local/share/Shalost/accounts/<аккаунт>/pulse-chrome-profile       (Linux)

Не передавайте содержимое этих папок: в них могут быть данные авторизации. Кнопка «Выйти» удаляет профиль аккаунта и требует войти заново. Срок жизни сессии определяет сервер Pulse.

## Логи

В интерфейсе выводятся рабочие события UI, AUTH, SCAN, PULSE, PRESENCE, LECTURE и BOT. Полная диагностика сохраняется в файле `pulseqr.log`:

- в portable-версии — рядом с `Shalost-FOTUR.exe` или `Shalost-FOTUR`;
- в установленной версии — в `%LOCALAPPDATA%\Shalost\pulseqr.log` на Windows и в `~/.local/share/Shalost/pulseqr.log` на Linux;
- в AppImage — всегда в `~/.local/share/Shalost/pulseqr.log`, потому что сам образ доступен только для чтения.

Когда автоматический вход не удаётся, в журнал попадает адрес страницы и список видимых полей и кнопок без значений — по нему видно, где именно остановился вход.

## Сборка из исходников

Требуется Python 3.11+ и Google Chrome или Chromium.

Linux:

    python -m pip install -r requirements.txt pyinstaller
    pyinstaller --noconfirm --clean --onedir --exclude-module numpy --hidden-import PIL._tkinter_finder --add-data "assets/shalost-fotur.ico:assets" --add-data "assets/shalost-fotur.png:assets" --name Shalost-FOTUR main.py

Windows:

    python -m pip install -r requirements.txt pyinstaller
    pyinstaller --noconfirm --clean --onedir --windowed --exclude-module numpy --icon assets/shalost-fotur.ico --add-data "assets/shalost-fotur.ico;assets" --add-data "assets/shalost-fotur.png;assets" --name Shalost-FOTUR main.py

AppImage собирается из готовой папки `dist/Shalost-FOTUR`:

    APPIMAGETOOL=/путь/к/appimagetool packaging/linux/build-appimage.sh

Сборкой занимается один сценарий GitHub Actions `build.yml`: при push в `main`, в pull request и вручную он собирает обе системы и проверяет, что приложение запускается — в Linux под Xvfb, в Windows обычным запуском. Готовые файлы остаются артефактами сборки.

После push тега вида `v0.1.0` тот же сценарий публикует релиз: установщик и ZIP для Windows, tar.gz и AppImage для Linux.

## Устройство проекта

    main.py              точка входа
    shalost/paths.py     пути приложения и журнал
    shalost/settings.py  настройки и список аккаунтов
    shalost/passwords.py пароли и токены в системном хранилище
    shalost/pulse.py     разбор QR и подтверждение присутствия
    shalost/browser.py   запуск профиля Chrome и поиск элементов на страницах
    shalost/login.py     вход сохранёнными данными, включая код 2FA
    shalost/screen.py    снимок экранов и клик по точке рабочего стола
    shalost/telegram.py  бот: уведомления, команды и кнопки
    shalost/ui.py        окно приложения и сценарии работы
    tests/               тесты на локальных страницах-заглушках

Тесты запускаются командой `python -m pytest`; те, которым нужен браузер,
пропускаются, если его нет в системе. Подробности — в [CONTRIBUTING](CONTRIBUTING.md).
