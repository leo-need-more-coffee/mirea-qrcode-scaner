# Shalost FOTUR

Локальное приложение для Windows и Linux для работы со своим аккаунтом Pulse РТУ МИРЭА: вход через официальный сайт, поиск QR-кодов на экранах и отправка подтверждения присутствия.

> Проект не связан с РТУ МИРЭА и Pulse. Используйте его только для собственного аккаунта и в соответствии с правилами учебного заведения.

## Что делает приложение

- Главный интерфейс запускается сразу и не зависит от загрузки Pulse.
- Вход выполняется в обычном окне официального Google Chrome, включая 2FA.
- После входа Chrome-профиль сохраняет сессию локально.
- При следующем запуске сессия проверяется автоматически через секунду.
- На главной показывается имя из Pulse, а кнопка входа скрывается.
- QR-коды Pulse ищутся на всех экранах раз в 2 секунды.
- Окно «Контроль присутствия» в MTS Link распознаётся на экране раз в 2 секунды; кнопка «ПОДТВЕРЖДАЮ» нажимается автоматически до исчезновения окна.
- Для трёх разных QR выполняются успешные подтверждения подряд. После третьего действует настраиваемая пауза, по умолчанию 10 минут. Повтор уже подтверждённого QR не засчитывается. Пауза не влияет на MTS Link.
- Понятный журнал остаётся в окне, полный технический журнал сохраняется в доступной для записи папке.
- В настройках есть путь к профилю, открытие папки, копирование пути и безопасный выход из аккаунта.
- Кнопка «Открыть лекцию» открывает СДО и Pulse в одном окне браузера: QR и кнопка «ПОДТВЕРЖДАЮ» ищутся прямо во вкладках, без снимков экрана.
- Аккаунтов может быть несколько: у каждого свой профиль Chrome, а найденный QR подтверждается за все отмеченные аккаунты.
- Сохранённые логин и пароль подставляются в форму входа, код двухфакторной проверки приложение спрашивает у пользователя.
- Телеграм-бот присылает события и принимает команды управления.
- Добавлены ссылки на FOTUR VPN и CloudTips QR.

## Установка и первый вход в Windows

Нужен Windows 10/11 и установленный Google Chrome.

1. Скачайте сборку из Releases:
   - Shalost-FOTUR-Setup-…exe — установщик с ярлыком;
   - Shalost-FOTUR-portable.zip — portable-вариант. Распакуйте архив целиком и запустите Shalost-FOTUR.exe.
2. Откройте приложение. Главный экран должен появиться сразу.
3. Нажмите «Войти в Pulse». Откроется отдельное официальное окно Chrome.
4. Войдите обычным способом и завершите 2FA. После обнаружения входа окно Chrome закроется, а на главной появится статус Pulse: …
5. Нажмите «Начать сканирование». Кнопка станет кнопкой остановки.

Cookie вручную копировать не нужно. Если Chrome или Pulse вернул ошибку, откройте нижний журнал: статус и причина остаются видны, а поиск QR продолжится.

## Установка и первый вход в Linux

Нужен x86-64 дистрибутив с glibc 2.35 или новее и установленный Google Chrome либо Chromium: приложение берёт первый найденный браузер из PATH.

1. Скачайте сборку из Releases:
   - Shalost-FOTUR-x86_64.AppImage — один файл, `chmod +x` и запуск;
   - Shalost-FOTUR-linux-x86_64.tar.gz — portable-вариант. Распакуйте архив и запустите `./Shalost-FOTUR` либо `./install.sh` для ярлыка в меню приложений.
2. Дальше всё как в Windows: «Войти в Pulse», вход и 2FA в открывшемся окне браузера.

Если AppImage не запускается из-за отсутствия FUSE, используйте `./Shalost-FOTUR-x86_64.AppImage --appimage-extract-and-run`.

### Режим лекции и снимки экрана

Кнопка «Открыть лекцию» открывает окно браузера со вкладками СДО (online-edu.mirea.ru) и Pulse. Войдите в обе и запустите занятие в этом же окне: приложение само нажимает «ПОДТВЕРЖДАЮ» в MTS Link и распознаёт QR прямо во вкладках. Этот режим работает в любом сеансе, включая Wayland.

Ссылка на занятие вводится на главном экране рядом с кнопкой: она открывается третьей вкладкой и запоминается до следующего раза. Кнопка присутствия нажимается и в неактивной вкладке: Chrome не доставляет туда настоящие события мыши, поэтому приложение использует событие страницы.

Кнопка «Начать сканирование» ищет QR на всех экранах — она нужна для QR с проектора в аудитории. Снимок экрана и автоклик выполняются через X11, поэтому в сеансе Wayland они недоступны: войдите в сеанс X11. Приложение пишет об этом в журнал. Для автоклика достаточно системных библиотек X11 и XTEST, при их отсутствии используется `xdotool`.

## Несколько аккаунтов

Один компьютер на двоих — обычное дело, поэтому аккаунтов может быть сколько угодно. На странице «Настройки» есть список аккаунтов:

- «Добавить аккаунт» создаёт новый профиль Chrome с собственной сессией;
- точкой отмечается активный аккаунт — с ним работают кнопки «Войти в Pulse» и «Открыть лекцию»;
- отметка QR означает, что аккаунт подтверждает найденный код. Один QR подтверждается за все отмеченные аккаунты по очереди;
- «Пароль» сохраняет логин и пароль аккаунта для автоматического входа;
- «Выйти» удаляет сессию аккаунта, «Удалить» — сам аккаунт вместе с профилем и сохранённым паролем.

## Автоматический вход

Если для аккаунта сохранены логин и пароль, приложение само заполняет форму входа в открытом окне Chrome. Pulse и СДО пользуются одним входом, поэтому в режиме лекции вкладка СДО входит теми же данными.

Когда сайт просит код двухфакторной проверки, появляется окно с запросом кода. Тот же запрос уходит в Telegram, если бот подключён: код можно просто отправить сообщением, и окно закроется само. Без сохранённого пароля всё работает как раньше — вход выполняется вручную.

Если сессия аккаунта потерялась, а пароль сохранён, приложение входит само: без окна браузера, при очередной проверке сессии или по команде `/login`. Код двухфакторной проверки при этом приходит в Telegram, поэтому вернуть сессию можно, не подходя к компьютеру. Повторная попытка для одного аккаунта делается не чаще раза в десять минут, чтобы не долбить сайт при неверном пароле.

Пароль хранится в системном хранилище: Credential Manager в Windows, KWallet или GNOME Keyring в Linux. В файлах приложения пароля нет, в `settings.json` попадает только логин. Если системного хранилища нет, приложение сообщит об этом и предложит входить вручную.

Помните, что сохранённый пароль доступен любому, кто работает под вашей учётной записью в системе.

## Управление из Telegram

Приложение умеет отчитываться о событиях и принимать команды из личного чата с вашим ботом.

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. В настройках нажмите «Подключить бота» и вставьте токен.
3. Приложение покажет код привязки. Отправьте боту `/start <код>` — чат привяжется.

Команды: `/status` — что сейчас происходит, `/login` — проверить сессии и войти заново, `/scan` и `/stop` — поиск QR на экранах, `/lecture` и `/close` — окно лекции. `/lecture <ссылка>` запоминает ссылку на занятие и открывает её. Когда приложение ждёт код двухфакторной проверки, обычное сообщение с кодом уходит в форму входа. В чат уходят события подтверждения QR, присутствия в MTS Link и входа в аккаунты.

Команды выполняются только из привязанного чата, остальные сообщения игнорируются. Токен бота хранится в системном хранилище рядом с паролями аккаунтов. Бот управляет приложением на вашем компьютере, поэтому работает, только пока оно запущено.

## Сессия и приватность

Сессия хранится только в профиле Chrome:

    %LOCALAPPDATA%\Shalost\accounts\<аккаунт>\pulse-chrome-profile      (Windows)
    ~/.local/share/Shalost/accounts/<аккаунт>/pulse-chrome-profile       (Linux)

Профиль прежних версий переносится в папку первого аккаунта при первом запуске.

Не передавайте содержимое этой папки: в нём могут быть данные авторизации. Кнопка «Выйти» удаляет этот профиль и требует войти заново. Срок жизни сессии определяется сервером Pulse; приложение не может его продлить и проверяет сессию при старте.

## Логи

В интерфейсе выводятся только рабочие события UI, AUTH, SCAN и PULSE. Полная диагностика сохраняется в файле `pulseqr.log`:

- в portable-версии — рядом с `Shalost-FOTUR.exe` или `Shalost-FOTUR`;
- в установленной версии — в `%LOCALAPPDATA%\Shalost\pulseqr.log` на Windows и в `~/.local/share/Shalost/pulseqr.log` на Linux;
- в AppImage — всегда в `~/.local/share/Shalost/pulseqr.log`, потому что сам образ доступен только для чтения.

Это позволяет не засорять экран техническими ошибками, но сохраняет данные для отладки. Установленная версия не пытается записывать журналы в `Program Files`.

## Сборка из исходников

Требуется Python 3.11+ и Google Chrome.

    python -m pip install -r requirements.txt pyinstaller
    pyinstaller --noconfirm --clean --onedir --windowed --exclude-module numpy --icon assets/shalost-fotur.ico --add-data "assets/cloudtips-donation-qr.png;assets" --add-data "assets/shalost-fotur.ico;assets" --add-data "assets/shalost-fotur.png;assets" --name Shalost-FOTUR main.py

Готовая portable-папка появится в dist\Shalost-FOTUR. Сценарий GitHub Actions автоматически создаёт и portable ZIP, и обычный установщик после push тега вида v0.1.0.

Сборка в Linux отличается разделителем в `--add-data` и не использует значок ICO:

    python -m pip install -r requirements.txt pyinstaller
    pyinstaller --noconfirm --clean --onedir --exclude-module numpy --hidden-import PIL._tkinter_finder --add-data "assets/cloudtips-donation-qr.png:assets" --add-data "assets/shalost-fotur.ico:assets" --add-data "assets/shalost-fotur.png:assets" --name Shalost-FOTUR main.py

AppImage собирается из готовой папки `dist/Shalost-FOTUR`:

    APPIMAGETOOL=/путь/к/appimagetool packaging/linux/build-appimage.sh

Сценарий GitHub Actions `build-linux.yml` делает то же самое и публикует tar.gz и AppImage после push тега вида v0.1.0.
